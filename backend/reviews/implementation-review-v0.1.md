## Findings

1. **P1 — Unsupported multi-token ATF constructs leak exact readings.** `cuneiform/adapters.py:77–88` tracks square brackets only and classifies each whitespace token independently. Reproduced in memory with `{"_id":"T","atf":"1. <<A B C D>>"}`: B and C become ordinary `reading` positions and `motif(db,['B','C'])['occurrences']` is **1**. The same happens inside `1. {(A B C D)}`. Retained official `evidence/ebl-atf-doc:276–328, 380–449` defines removal and document-oriented gloss spans; internal words cannot silently become ordinary text occurrences. Only the opening/closing whitespace tokens are excluded. This contradicts the conservative blocking-position claim and can create false source-reading motifs, even though raw trace still round-trips. Track unsupported span context and block its interior (or reject/account the affected line); full grammar implementation is unnecessary. Add regressions for internal exact matches, including spans longer than two tokens.

2. **P2 — Supported-looking translation lines disappear without exclusion accounting.** `cuneiform/adapters.py:61–70` recognizes only `#tr.<language>:` but exempts every `#tr.` line from exclusions. Reproduced `1. A B\n#tr.en.(1): translation`: zero translation rows and zero exclusions. Retained official grammar at `evidence/ebl-atf-doc:198–205` explicitly permits translation extents. Preserve such strings as unresolved translations or emit an explicit unsupported-line exclusion. Raw retention alone does not substantiate complete translation/exclusion accounting.

3. **P2 — Snapshot verification trusts an incomplete manifest and does not bind metadata to snapshot identity.** `cuneiform/storage.py:42–49, 57–59, 145–150`. A read-only mock of `Path.read_text` returning `{"schema_version":"1","files":{}}` makes `verify(Path('/nonexistent/review-no-write'))` succeed with no payload reads. Removing the graph/raw entries from a real manifest would similarly disable their checksum checks; editing source citation, rights, counts, raw hash or snapshot ID is not detected. Existing-snapshot reuse trusts this result. Require the full manifest contract and mandatory payload set, raw-hash consistency, parser/schema compatibility, and a recomputed identity matching the requested snapshot. Distinguish payload checksum verification from authenticated manifest integrity: malicious coordinated rewrites need an independently trusted digest, not another self-declared hash. This finding was reproduced with mocks only; real disk tamper behavior remains unrun.

4. **P2 — Input admission and import operate on different reads.** `cuneiform/storage.py:34–39, 53–65`; same pattern in `cuneiform/demo.py:11–12`. Inspection stats/reads the file, then import rereads it without checking the new length or recomputing admission estimates. Mocking the two `Path.read_bytes` calls with a small valid object followed by a 3 MiB valid JSON input makes dry-run return successfully despite the 2 MiB cap, with the original small estimate. A growing/replaced local input can therefore bypass the bounded-input guarantee and invalidate the storage estimate before ingestion. Read once with a bounded read of cap+1 bytes and derive inspection, hash, parsing and admission from those same bytes. The stat/read pair alone is also racy. No disk writes were needed for this reproduction.
